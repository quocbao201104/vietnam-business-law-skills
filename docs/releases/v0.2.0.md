# Vietnam Business Law Skills v0.2.0

This release hardens the runtime architecture introduced in v0.1.0 and packages the project for broader early dogfooding.

## Highlights

### Just-in-time runtime contracts

The skill no longer treats every schema/reference as an up-front read requirement. It keeps `SKILL.md` as the always-on kernel and loads additional contracts only when their governed behavior becomes material.

Important coupled loads are preserved:

- authority work loads Legal Work State plus authority/search/source contracts;
- specialist invocation loads Legal Work State plus the specialist-handoff contract;
- multi-owner composition loads composition/state contracts when required;
- runtime trace remains an evaluation/audit surface rather than a normal-response preload.

Ordinary multi-step reasoning by itself is not a reason to load the state contract.

### Safer composition-conflict convergence

Composition conflicts now have three semantic outcomes:

```text
ACTIVE
RESOLVED
TERMINAL_UNRESOLVED
```

`ACTIVE` prevents convergence while a material internal resolution step remains available.

`TERMINAL_UNRESOLVED` is an explicit non-resolution endpoint for the current inputs. It may converge only when the remaining external fact, authority, input, or human judgment is explicit and every affected action has been recomputed to a non-READY state.

Conflict status/scope transitions are revision-safe. Reopening after later material input is explicit and auditable, and `DO_NOT_PROCEED` requires an independently supported blocker.

### Ownership is semantic, not deployment topology

BL1–BL8 are accountable decision roles, not mandatory separate agents.

One assistant/runtime may sequentially execute several BL roles while preserving:

- proposition ownership;
- owner-scoped mutation;
- stable IDs and state revisions;
- contradiction/reclassification return-to-owner rules;
- authority applicability separation;
- specialist return semantics;
- per-action readiness and convergence.

Multi-agent execution remains optional.

### Stronger trace validation

The runtime trace/checker now more strictly validates:

- owner assignment and routing boundaries;
- revision-safe `STATE_DELTA` linkage;
- conflict terminalization/resolution/reopening;
- affected-action scope continuity;
- post-conflict readiness recomputation;
- independent blocker evidence for `DO_NOT_PROCEED`;
- observable path correctness without exposing hidden chain-of-thought.

### Plugin packaging and project roadmap

The repository now includes Claude Code and Codex plugin packaging backed by the same runtime skill files, plus a public capability roadmap for future practitioner capabilities, domain depth, legal operations, and evidence-gated specialist work.

## What did not change

The release does **not** replace the BL1–BL8 reasoning kernel or turn the repository into a static legal encyclopedia.

Core principles remain:

```text
Stable reasoning, live law.
One material proposition → one accountable owner.
Current/binding authority ≠ applicable-to-case authority.
Agreement ≠ regulatory permission.
Fact proposition ≠ evidence provenance.
Readiness is per action.
```

## Status

v0.2.0 is intended for **early dogfooding and real-world evaluation**.

The architecture and observable runtime contracts are materially stronger than v0.1.0, but this release is not a claim of exhaustive Vietnamese-law coverage, complete sector specialization, or final candidate-bound runtime proof across every path.

## Upgrade notes

If you installed the repository as a Claude Code or Codex plugin, refresh/update the repository-backed plugin to pick up v0.2.0.

No migration of user legal data is required. The main compatibility change is behavioral: runtimes should respect the newer JIT contract-loading, conflict lifecycle, revision linkage, and semantic-owner rules.
